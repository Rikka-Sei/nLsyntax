# nLsyntax 写法对比实验（2026-10-13）

## 要回答的问题

几个开源项目对"让模型说人话"用了不同做法。哪种写法放进 skill 效果最好？

| 版本 | 内容 | 借鉴来源 |
|---|---|---|
| V0 | 不加 skill | 基线 |
| V1 | 三问判定原则 + 约束词表 | nLsyntax 初版 |
| V2 | 只有原则，不给词表 | shuorenhua v2.5："按内容判断，不按命中词替换" |
| V3 | V1 + 起草→逐句审查→五项自评打分→定稿 | humanizer 的多遍流程、stop-slop 的打分 |
| V4 | V1 + 每次回答强制运行检查脚本，改到无"禁用"命中 | avoid-ai-writing 的检测器 |
| V5 | V1 + 从 V0 输出中挖出的新词 + 处理用户文本的两种模式 | slop-forensics 的挖词方法、avoid-ai-writing 和 shuorenhua 的模式划分 |

## 方法

- **生成**：每个版本由一个独立的子代理作答。子代理只看到自己那个版本的 skill 和题目，不知道实验目的。
- **评审**：所有回答打乱顺序，换成随机编号后，交给两名不知道版本的评审分别打分。评分项包括：
  - 需要读者解码的表达（逐处列出）
  - 自然、具体、有用三项，各 1–5 分
  - 是否过度纠正
  - 第三轮起加了一项：是否满足用户的明确要求
- **防作弊**：事先定好一份 48 条的留出词表（`tests/heldout.json`），和约束词表没有重叠，用来检验 skill 对表外说法的处理能力。评审对"需要解码的表达"也是自行判断，不参考词表。
- **评审一致性**：两名评审对"需要解码的表达"的计数，三轮的相关系数分别是 0.97、0.91、0.99。

## 结果

需要解码的表达 = 每题平均处数（两名评审取平均）。质量分 = 自然、具体、有用三项的平均。

**第一轮**：12 道题，sonnet 生成

| 版本 | 需要解码 | 自然 | 具体 | 有用 |
|---|---|---|---|---|
| V0 | 2.92 | 4.00 | 4.08 | 4.38 |
| V1 | 0.08 | 5.00 | 4.71 | 4.96 |
| V2 | 0.00 | 5.00 | 4.88 | 5.00 |
| V3 | 0.04 | 5.00 | 4.83 | 4.83 |
| V4 | 0.08 | 5.00 | 4.83 | 5.00 |

除 V0 外，各版本都接近满分，分不出高下。

**第二轮**：8 道更难的新题，haiku 生成。题目包括长文、提问本身满是黑话、写给外行看等情况。

| 版本 | 需要解码 | 自然 | 具体 | 有用 |
|---|---|---|---|---|
| V0 | 3.06 | 3.62 | 3.69 | 3.81 |
| V1 | **0.00** | 5.00 | 5.00 | 5.00 |
| V2 | 0.62 | 4.75 | 4.56 | 4.75 |
| V3 | 0.31 | 5.00 | 4.81 | 4.88 |
| V4 | 0.31 | 4.88 | 4.50 | 4.81 |

换成较弱的模型后，只给原则的 V2 明显退步。它漏掉的"被看到""承压""倒逼"都属于词表覆盖的类别。

**两轮合并（20 道题，按题配对做置换检验）**

- V1 对 V0：需要解码的表达每题少 2.92 处，p < 0.001。20 道题里 V1 有 17 道更少，没有一道更多。
- V1 对 V2、V3、V4：V1 的数值都更好，需要解码的表达每题少 0.10 到 0.20 处，但 p 都大于 0.25。按这个样本量，只能说 V1 不比它们差。

**第三轮**：8 道新题，haiku 生成，验证最终版

| 版本 | 需要解码 | 自然 | 具体 | 有用 | 满足要求 |
|---|---|---|---|---|---|
| V0 | 2.38 | 4.31 | 3.94 | 4.25 | 4.88 |
| V1 | 0.25 | 4.81 | 4.75 | 4.69 | 4.81 |
| V5 | **0.12** | 4.75 | 4.62 | 4.44 | 4.75 |

V5 的残留最少。它的"有用"分略低于 V1，主要原因是第三轮暴露出的两个问题：

1. "只标注"模式的说明写成了"给出替换写法"。用户明确说"不用改写"时，模型仍然给了替换写法。
2. 原来的提示让模型把"兜底"换成"保底"，评审认为这仍是黑话。

**针对这两处的复测**（修改后用新题测试，一名评审）

- "只标注"类 2 题：满足要求 5/5，没有再给替换写法。
- "只改用词"类：第一次复测发现，模型把词表"改成"列里的描述原样贴进句子，导致句子变长、语法不通。在 skill 里说明"改成列是方向，不是可以原样贴进句子的词"之后，换 4 道没出现过的题再测，满足要求的平均分是 4.25：2 道满分，没有语法错误。剩下的扣分都发生在黑话叠用的句子上，比如"对齐颗粒度"，换成白话不可避免会变长。

## 结论与采用的做法

1. **加 skill 是收益最大的一步。** 需要解码的表达从每题约 3 处降到 0.3 处以下，自然度和有用度都上升，三轮里没有一次过度纠正。
2. **采用"三问原则 + 词表"。** 只给原则在较强的模型上够用，换到较弱的模型就会漏词，而且漏掉的正是词表覆盖的类别。
3. **不采用多遍审查和强制跑脚本。** 两者都没有带来可测的收益，却要多花步骤。强制跑脚本还让回答变短、具体程度最低，而且离开命令行环境就用不了。脚本只用于长文和改写用户给的文本。
4. **词表从真实输出里收集。** 第三轮里，V1 写出了"先上线最痛的一项"，V5 没有再犯，因为这个说法是从前两轮 V0 的输出里收进词表的。
5. **词表的"改成"列只写方向，并在 skill 里明说这一点。** 否则较弱的模型会把描述原样贴进句子。

## 局限

- 每轮只有 8 到 12 道题。V1、V3、V4、V5 之间的差距在统计上不显著。
- 生成模型只测了 sonnet 和 haiku，评审都是同一系列的模型。
- 复测只用了一名评审。
- 原始数据（题目、各版本 skill、回答、评分、版本对应表）在实验数据包里。
